核心研究判断

2026年9月的通用个人 Agent 已跨过概念验证期，进入“真实工作可用、仍需人类监督”的阶段。核心竞争点从回答质量转向任务成功率、人工介入、失败恢复、长期状态、安全边界和单位成功任务成本。

一、执行摘要

通用任务型个人 Agent 的本质是把推理模型、浏览器/电脑操作、工具调用、文件系统、代码执行、应用连接、记忆和任务调度组合成“目标—规划—行动—反馈—交付”闭环。用户不再只问“答案是什么”，而是直接提出“结果是什么”。

市场目前形成三类路径：第一类是超级助手型，如 ChatGPT Work、Gemini Agent、Claude/Cowork、Perplexity Computer；第二类是云端数字员工型，如 Manus、Genspark、Kimi Agent；第三类是浏览器/电脑接管型，如 Comet、Kimi Work、QwenWork、Claude in Chrome。三类产品边界正在快速融合。[S01][S04][S10][S16][S19][S20][S23]

判断产品成熟度时，五个问题比“有没有Agent模式”更重要：能否跨工具持续执行、能否错误恢复、能否安全执行有副作用的动作、能否保留任务状态、能否让用户理解和干预执行过程。[S27][S28]

二、报告范围与研究方法

纳入产品需要具备多步骤规划、外部工具/数据/文件/网页/应用访问、自主行动能力，并面向个人知识工作。固定RPA、纯聊天机器人、单一开发框架和仅面向企业后台的Agent仅作为邻接产品观察。

证据分级

A：官方产品页、帮助中心、开发文档；B：官方公告、研究、系统卡；C：公开Benchmark与行业研究。价格、功能、地区和套餐均按2026年9月20日前后可访问页面核验；动态页面后续可能变化。

研究原则

  • 官方公开资料优先，不对未公开能力做推断。
  • 模型Benchmark不直接等同消费者产品任务成功率。
  • “强/中/部分/待观察”属于研究判断，不是第三方权威评级。
  • 实际采购或个人长期使用应采用统一任务集进行实测。

三、通用任务型个人 Agent 的产品演进

L0 对话助手回答问题、生成内容；瓶颈是知识、上下文和幻觉。
L1 工作流助手固定流程、多工具串接；灵活性有限。
L2 浏览器 Agent看网页、点击、输入、滚动；受登录、网页变化和提示注入影响。
L3 电脑 Agent跨桌面应用、文件、终端；权限与可逆性成为核心问题。
L4 持续/多Agent后台运行、并行、记忆、技能、监控与交付。

为什么Computer Use是临界能力

大量真实办公场景没有API，或者API无法覆盖全部操作。GUI因此成为通用接口：Agent可以看屏幕、点击、拖拽、输入并在浏览器或桌面软件中完成任务。[S04][S05][S23] 但GUI执行同时增加了定位错误、动态网页、登录和提示注入风险。

长任务为什么需要并行

当任务被拆成研究、数据清洗、图表、写作、引用核验等子任务时，串行执行会把总耗时拉长。Manus、Kimi、Genspark等都在公开产品中强化并行/多Agent能力。[S15][S16][S19]

产品路线差异

ChatGPT Work更强调从目标直接走向交付；Gemini强化Google生态；Claude强调桌面知识工作与MCP；Perplexity强调研究与执行；Manus强调云端数字员工；Genspark强调工具箱与Skills；Kimi强调中文知识工作与Agent Swarm；QwenWork强调办公与直接电脑操控。[S01][S04][S07][S10][S14][S16][S19][S23]

五、产品能力拆解：从模型到Agent系统

1模型层推理、多模态、代码模型：理解目标并规划。
2工具层搜索、浏览器、文件、终端、Connectors：把思考变成行动。
3环境层云沙盒、远程桌面、本地电脑：提供执行场所。
4编排层Planner、Router、Orchestrator、Sub-agent：拆解、委派、并行、聚合。
5状态层上下文、项目、Memory、Skills：支撑长期任务。
6控制层审批、权限、Watch Mode、接管、预算：限制风险。
7评估层日志、Verifier、事实核验：判断是否真的完成。

“能做”与“做成”不是同一指标

能打开网页、能写Excel、能生成PPT只能证明动作空间存在；真正的产品价值要看一次任务是否达到验收标准、关键步骤是否正确、是否需要人工接管、是否返工，以及失败后能否恢复。

记忆与状态

长期记忆、项目状态和Skills使Agent从一次性工具变成长期助手，但也意味着更多个人数据被保存和调用。个性化与隐私因此是一对同时增长的能力与风险。[S11][S19]

从“问问题”变成“交付结果”

一个典型任务可以是：读取本地资料→搜索公开资料→建立证据表→分析数据→生成报告→制作PPT→检查数字和引用→输出最终文件。真正的Agent应承担其中大部分机械步骤，而不是只生成最后一段文字。

八、可靠性与Benchmark：为什么不能只看排行榜

OSWorld主要测开放式桌面GUI任务；WebArena/Verified主要测网页环境；GAIA偏综合知识与工具使用。[S31][S32] 三者环境不同，不能互相替代。

厂商公开Benchmark往往是模型、Agent框架、工具环境和提示策略的联合结果，不等于消费者产品在真实互联网任务中的成功率。因此本报告建议建立自己的任务集。

指标建议权重定义
任务完成率30%一次性达到验收标准的比例
关键步骤正确率20%登录、筛选、填写、提交等节点
事实/数字准确率15%与源数据一致的比例
人工介入率10%需要补充、纠正或接管的比例
返工率10%交付后必须大修的比例
平均耗时5%启动到交付时间
单位成功任务成本5%订阅/额度成本折算
风险事件率5%误操作、越权、数据暴露

九、安全、隐私与治理

Agent比聊天机器人多了真实行动能力，因此风险从“答错”扩展到“做错”。OpenAI公开安全材料和OWASP Agentic Applications风险框架均强调提示注入、数据外泄、错误操作、权限和供应链等问题。[S03][S33][S39]

机制解决的问题边界
人工确认降低购买、发送、提交等高影响误操作确认不等于用户真正理解风险
人工接管登录、敏感页面、复杂步骤增加操作成本
沙盒隔离执行环境沙盒中的数据仍可能敏感
最小权限降低数据和应用暴露用户容易一次授权过多
审计日志错误追踪和责任定位个人产品通常不如企业系统完整
预算/额度控制失控任务和成本额度不足会中断任务

本地 vs 云端

本地Agent通常更接近真实电脑环境，但权限与数据泄露风险更直接；云端沙盒更易隔离和长时间运行，但需要把工作资料上传或授权给服务。敏感资料应采用最小权限、专用目录和人工审批策略。

十、技术生态：MCP、A2A与Agent工具协议

MCP主要解决“Agent如何连接工具与数据”；A2A主要解决“Agent如何与另一个Agent协作”。[S29][S30] 二者不是竞争关系，而是不同层次的互操作协议。

维度MCPA2A
主要问题工具/数据连接Agent间协作
典型关系“让我调用一个工具”“让我委派给另一个Agent”
个人意义扩大工具生态形成专业Agent网络

长期看，产品竞争会从单模型能力扩展到连接器、Skills、工具生态、Agent Runtime和验证体系。生态能力越强，用户迁移成本越高。

十二、个人选型方法

第一问：信息问题还是行动问题？

如果主要是问答、写作、总结，传统高质量聊天模型已经足够；如果需要跨网站、文件、桌面应用执行，应优先观察Computer Use、Connectors和后台任务。

第二问：资料在哪里？

Google生态优先观察Gemini；Microsoft 365优先观察Copilot/Agents；本地文件与中文Office场景可重点测试Kimi Work/QwenWork；跨互联网研究可测试Perplexity/ChatGPT/Manus。

第三问：需要陪跑还是后台执行？

实时陪跑看过程可见性和接管；半自动看审批；后台自动看持久会话、定时和失败恢复。

第四问：能接受什么权限？

权限越高，潜在收益越大，风险也越大。购买、付款、发送邮件、发布内容、删除文件等动作应设置人工确认。

十三、个人Agent标准工作流模板

阶段应明确什么示例
目标最终交付输出20页行业分析报告
边界范围、时间、预算、禁区只用2025-2026公开资料
证据来源等级和引用规则关键数据必须有一手来源
执行允许搜索、代码、文件、工具读取指定目录并运行分析
验收质量门槛检查数字、引用、格式、图表

适合Agent的任务

规则明确、资料可访问、步骤可验证、错误可回滚、成果物有验收标准的任务最适合自动化。

不适合完全交给Agent的任务

不可逆金融操作、法律最终判断、重大人事决定、敏感数据处理和无法回滚的生产环境操作应保留人工控制。

十四、企业/组织导入Agent建议框架

层级建设内容关键问题
员工层入口、模板、Skills员工能否低门槛创建任务
工具层MCP/API/Connectors/Computer Use是否获取正确数据并执行
治理层身份、权限、审批、审计、预算谁允许Agent做什么
评估层真实任务集、自动检查、人工复核是否真正节省时间并控制风险

不建议从“买一个最强Agent”开始。应该先选5-20个高频真实任务，建立基线，再比较产品在任务完成率、人工介入、成本和风险上的变化。[S35][S36]

十五、未来12—24个月趋势

  1. 从单一Agent走向Agent Runtime：规划、路由、记忆、工具、验证成为统一运行时。
  2. 浏览器会成为Agent重要的“身体”：Computer Use覆盖越来越多没有API的工作。
  3. 个人Agent越来越长期化：Memory、Projects、Skills、Scheduled Tasks成为基础设施。
  4. Verifier/审计器与执行Agent同等重要：执行越强，验证越重要。
  5. Agent经济学最终落到单位成功任务成本，而不是模型token价格。

这些趋势是基于已公开路线的研究判断，不是对未来市场结果的预测。[S29][S37][S38]

十六、综合判断

截至2026年9月，通用个人Agent已经进入“真实工作可用、仍需人类监督”的阶段。它在研究、文档、网页操作、代码、数据分析和多工具协同方面明显超过传统聊天机器人，但“完成一次任务”和“稳定承担一个岗位”仍有明显差距。[S31][S34][S36]

真正的产品价值公式：理解目标 + 真实环境行动 + 状态保持与失败恢复 + 用户可控的权限、成本和验收。

任务记录指标

需要登录的网站任务人工接管是否正确触发
故意制造一步失败识别、恢复、最终成功

多Agent并行研究并行效率、重复工作、聚合质量

实际试用时建议把这套任务扩展到20项，并固定输入、验收标准和人工评分规则；不要用不同提示词分别“调教”每个产品后再比较。
