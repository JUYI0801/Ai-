真正值得比较的不是“谁回答最好”，而是“谁能更少人工介入地把任务做完并交付可验收结果”。

任务成功率 × 人工介入率 × 返工率 × 单位成功任务成本

治理临界能力

一、执行摘要

通用任务型个人 Agent 已进入“从回答问题到替用户完成工作”的产品阶段。其核心变化并不是单一模型参数增长，而是把推理模型、浏览器/电脑操作、工具调用、文件系统、代码执行、应用连接、记忆与定时任务组合成一个能够持续执行的闭环。OpenAI 将 Agent 定义为能够独立代表用户完成任务的系统；Anthropic 则进一步区分了“预先编排的工作流”和“由模型动态决定过程与工具使用的 Agent”。[S27][S28]

截至本报告时点，市场已经形成三类明显的产品路径。第一类是“超级助手型”，如 ChatGPT Work、Gemini Agent、Claude/Cowork、Perplexity Computer：入口仍然是对话，但背后增加了网页、桌面、文件和应用操作能力。第二类是“云端数字员工型”，如 Manus、Genspark Super Agent、Kimi Agent：强调长任务、后台执行、多 Agent 协同和最终交付物。第三类是“电脑/浏览器接管型”，如 Comet、Kimi Work、QwenWork，以及 Claude in Chrome 等：通过浏览器或桌面环境把 Agent 从云端的信息处理推进到实际软件操作。[S01][S04][S10][S16][S19][S20][S23]

从产品能力成熟度看，真正的分水岭已经不是“有没有 Agent 模式”，而是五项能力：①能否跨多个工具持续执行；②能否在出错后恢复；③能否安全地执行具有副作用的操作；④能否保留项目/任务状态并持续运行；⑤能否让用户理解、干预和审计 Agent 的行为。公开研究也表明，Agent 的可靠性仍然没有达到“高风险任务可完全无人值守”的水平。Stanford 2026 AI Index 指出，AI Agents 在相关评测中仍大约每三次任务失败一次；Deloitte 2026 调查显示，约80%的受访组织尚缺少成熟的 Agent 治理能力。[S34][S36]

商业模式正在从“模型订阅”向“算力/任务容量订阅”转变。ChatGPT、Claude、Gemini、Perplexity 等保持订阅体系，同时用使用上限管理长任务成本；Manus、Genspark、Kimi、QwenWork 等更明确采用 Credits/额度池。高端 Agent 订阅价格已经出现每月100—200美元甚至更高的档位，反映长任务、多模型并行、浏览器操作、代码运行和后台任务带来的真实计算成本。[S02][S06][S11][S12][S13][S17][S21][S22]

对个人用户而言，Agent 的价值最适合用“节省的人工步骤”衡量，而不是单纯比较模型回答质量。能够把“搜索—筛选—整理—写作—制表—制作PPT—发送/提交—复盘”串成闭环的产品，才具有明显的 Agent 属性；只有生成一段答案、给出建议、提供一个文本草稿的产品，即便内部使用了 Agent 技术，也不一定属于真正的通用任务执行型 Agent。

核心结论

结论事实依据对产品判断的含义
Agent 正从“聊天工具”进入“执行层”ChatGPT Work可跨应用与文件完成任务并持续数小时；Perplexity Computer可执行完整工作流；Kimi Work可读本地文件、操作浏览器、运行代码并执行定时任务。[S01][S10][S20]产品竞争焦点由“回答质量”转向“任务成功率、工具广度和执行闭环”。
“Computer Use”成为通用 Agent 的关键基础能力QwenWork可看懂屏幕、点击、拖拽、输入，并在后台运行；Google将Computer Use集成到Gemini模型工具链。[S23][S04]未来Agent不必等每个软件都提供API，GUI本身会成为通用接口。
长任务的并行化是主要效率杠杆Manus广泛研究支持最多20个子任务并行；Kimi Agent Swarm支持大规模子Agent并行；Genspark支持多任务并行。[S15][S19][S16]单Agent串行执行的效率瓶颈正在转向“编排器＋子Agent＋聚合器”。
安全问题随“行动能力”而非单纯模型能力增长OpenAI把提示注入、数据外泄和错误操作列为Agent核心风险；OWASP 2026专门形成Agentic Applications风险框架。[S03][S33]权限、审批、沙箱、审计必须成为产品的一部分，而不能依赖用户自行判断。
Agent市场尚未形成统一评价体系OSWorld、WebArena-Verified等分别测GUI和网页；不同产品使用不同模型、工具和提示策略，benchmark不可直接等价为产品成功率。[S31][S32]采购和选型必须采用任务集实测，而不是只看厂商榜单或模型benchmark。

二、报告范围与研究方法

本报告将“通用任务型个人 Agent”定义为：用户以自然语言提出目标后，系统能够自主分解任务、选择工具、获取环境反馈、持续执行多个步骤，并最终交付可验证的结果；必要时在关键节点向用户请求确认、补充信息或人工接管。该定义强调“目标—规划—行动—反馈—交付”闭环，而不是是否使用了某个特定模型或某个营销名称。[S27][S28]

2.1 纳入范围

具备多步骤任务规划和执行能力；

可以访问至少一种外部工具/数据源/文件/网页/应用；

具有一定程度的自主行动能力，而不只是按固定脚本运行；

面向个人或个人知识工作场景，或同时提供明显的个人使用入口；

能够交付文档、表格、PPT、代码、网页、数据分析结果或其他可消费成果。

2.2 不纳入或只作为邻接产品分析

纯聊天/问答产品；

仅具备单一步骤生成能力的写作、绘图、视频生成工具；

纯企业后台 Agent 平台，但没有个人用户入口；

纯开发者 Agent 平台（仅作为技术生态参考）；

固定规则自动化工具（如传统RPA）——可与Agent结合，但不属于本报告重点。

2.3 证据分级

A级：官方产品页、官方帮助中心、官方文档；B级：官方产品公告、官方研究/系统卡；C级：公开基准平台、学术论文、行业研究；D级：媒体、社区或用户体验。报告涉及产品功能、价格、限制、可用地区等事实时，优先使用A/B级证据；C级仅用于基准和行业背景；没有足够证据的项目标记为“未公开/待实测”，不推断。

2.4 研究时点与动态信息原则

报告以2026年9月20日为核验截点。由于Agent产品更新速度很快，价格、额度、地区、模型和功能均可能变化；因此报告对“当前价格”采用“公开页面当前值”的口径，并在涉及价格时标注“起价/档位/参考值”，不把它视为长期固定价格。[S02][S06][S12][S17][S21]

三、通用任务型个人 Agent 的产品演进

3.1 从 Chat 到 Agent 的四级演进

层级典型特征用户动作系统动作主要瓶颈
L0 对话助手回答问题、生成文字/图片提问生成答案知识、上下文与幻觉
L1 工作流助手固定流程、多工具串接指定步骤或模板按既定路径调用工具灵活性不足
L2 浏览器 Agent能够看网页并点击、输入、滚动给目标规划并操作网页网页变化、登录、提示注入、UI定位
L3 电脑 Agent能操作桌面应用、文件、浏览器、终端给结果目标跨应用执行、运行代码、读写文件权限、可逆性、错误恢复
L4 持续型/多Agent长时任务、后台运行、并行子Agent、记忆与技能给长期目标拆分、委派、并行、监控、复盘、交付成本、状态一致性、安全、治理

从公开产品形态看，2026年的主流产品已经普遍进入L2-L4的不同组合阶段：ChatGPT Work、Perplexity Computer、Kimi Work、QwenWork明显强化了电脑/桌面执行；Manus、Genspark、Kimi把多Agent、长任务和成果交付作为卖点；Gemini Agent、Claude Cowork则把Agent能力嵌入既有助手生态。[S01][S10][S16][S19][S20][S23]

3.2 为什么“Computer Use”会成为通用 Agent 的临界能力

API是机器之间的标准接口，但个人实际工作环境大量依赖网页后台、桌面软件、旧系统、第三方网站、企业内部系统和无法轻易标准化的GUI。Computer Use通过截图/视觉理解＋鼠标键盘动作，使Agent可以在没有专用API的情况下与真实软件交互。QwenWork的官方文档明确支持屏幕感知、点击、双击、拖拽、输入、快捷键以及后台执行；Google也将Computer Use纳入Gemini工具体系。[S23][S04]

因此，未来通用Agent的工具获取路径将同时存在三条：API/MCP等结构化工具；浏览器自动化；Computer Use/桌面自动化。三者不是互斥关系，而是从高可靠、高结构化到高通用、低结构化的不同执行层。

4.2 ChatGPT Work / ChatGPT Agent

ChatGPT Agent在2025年7月将Operator的浏览器执行、deep research的研究能力、受限终端以及Connectors整合起来；2026年7月进一步推出ChatGPT Work，定位为能够跨应用与文件执行更长时间、更复杂工作的Agent，并能够生成文档、电子表格、演示文稿、报告和Sites；Work还支持Scheduled Tasks，以一次性、周期或触发式方式继续推进工作。[S01][S03][S02]

产品适配

适合“信息研究＋跨文件分析＋最终交付”的知识工作闭环；优势来自统一入口、较完整的工具生态和成熟的人工接管机制。

主要边界与风险

需要重点关注使用额度、连接器权限、登录态以及提示注入。OpenAI官方明确指出，Agent可访问邮件、文件、账户设置等敏感数据，因此采用用户确认、Watch Mode、终端网络限制等措施；这些措施降低风险但不会将风险降为零。[S03][S39]

4.3 Gemini Agent / Project Mariner

产品适配

核心优势在Google Search、Gmail、Calendar、Docs等原生生态的深度结合，适合“个人信息＋互联网＋Google工具”一体化场景。

主要边界与风险

需要区分实验/正式能力；Gemini Agent公开页面说明其当前面向Google AI Ultra、美国、英语环境。Google AI计划当前提供Pro与Ultra多级访问量，Ultra的Gemini Agent权限高于Pro。[S04][S06]

4.4 Claude Cowork + Claude in Chrome

Anthropic在2026年将Cowork定位为把Claude的执行能力带到桌面知识工作场景，并持续扩展Claude in Chrome。官方说明区分本地Desktop Extensions与Remote Connectors：前者可访问本地文件、应用和系统资源；后者连接云服务和在线应用。Claude还支持直接创建/编辑Excel、文档、PowerPoint和PDF等文件。[S07][S08][S09A]

产品适配

对本地文件、桌面知识工作、长文本和跨Office任务具有明显适配性；MCP/Connectors是其工具扩展核心。

主要边界与风险

“本地扩展”与“远程连接器”的权限边界需要分别治理；本地数据并不等于所有Agent逻辑都在设备本地运行，企业仍需检查具体扩展、认证方式和传输范围。[S08]

价格/额度

Anthropic当前公开定价包括Pro、Max、Team、Enterprise等档位；Max从100美元/月起，Team为25美元/人/月（年付，月付30美元），具体权益与地区税费以当前定价页为准。[S09]

4.5 Perplexity Computer / Comet

Perplexity Computer将搜索、研究、浏览器自动化、代码、创建应用和长期任务整合成数字工作者；官方页面称可执行持续数小时甚至数月的完整工作流，并支持后台任务、周期任务、并行研究、连接Gmail/Slack/Notion/Calendar以及个性化Skills。[S10] Comet则是以浏览器为入口的个人AI助手。[S10]

产品适配

其核心差异是“研究→执行”链路非常短，搜索来源与Agent行动天然结合。对于市场调研、竞品资料搜集、信息监控等任务，产品形态高度契合。

主要边界与风险

Perplexity的优势高度依赖连接器、搜索与Computer执行层；因此高强度任务的额度与成本需要持续关注。Max还提供Brain记忆系统，为Computer提供工作上下文。[S11]

价格/额度

Pro当前公开价格20美元/月；Max 200美元/月。Pro含扩展Computer访问和4,000奖励积分，Max提供更高Computer用量、35,000奖励积分以及10,000/月Computer积分等。[S12][S11]

4.6 Manus

Manus将Agent Mode与Chat Mode明确区分。Agent Mode用于复杂任务、网站、Slides、视频等，并以自动规划和多步骤执行为核心；2026年3月的帮助资料还显示广泛研究可把复杂任务拆成并行子任务，最多同时运行20个子任务。[S14][S15]

产品适配

更像“云端数字员工工作站”，强调任务启动后自主执行和最终成果交付。

主要边界与风险

其沙盒化工作环境便于运行代码、生成网站和处理文件；同时通过积分机制把不同复杂度的任务成本显性化。

Super Agent被定义为可自主思考、规划、调用工具并完成研究、内容、分析、设计、编码、沟通等工作的通用助手。新版Super Agent支持专用沙盒环境、浏览器、文件系统、代码执行、多任务并行以及将工作流保存为可复用Skill。[S16]

产品适配

5.2 “能做”与“做成”是两个不同指标

Agent产品演示通常展示“能够完成某任务”，但产品采购或长期使用真正关心的是任务成功率、返工率、平均耗时、失败恢复能力、关键步骤的人类介入比例以及单位任务成本。Anthropic关于Agent设计的经验指出，Agent的自主性会带来更高成本和“错误累积”风险，因此应使用沙箱、清晰的工具接口和持续评测；OpenAI也把“完成任务”而非单纯回答作为Agent的核心定义。[S27][S28]

5.3 长任务为什么必须引入并行与子Agent

复杂任务通常存在天然可并行的子任务，例如“找10家竞品→分别提取价格、功能、评价→汇总比较”。串行执行会把总耗时近似叠加；并行执行则可把总时延压缩到最长子任务加协调开销。Manus公开资料显示其广泛研究最多20个子任务并行；Kimi Agent Swarm公开支持大量子Agent协作。[S15][S19]

但是并行并非无成本。并行数量越大，越容易出现重复搜索、结果冲突、上下文合并、成本增长和错误放大。因此“多Agent”不应该简单理解为“Agent越多越好”，真正需要优化的是任务分解质量、子任务独立性、合并策略和终止条件。

5.4 记忆：个性化的核心，也是隐私的核心

Agent中的“记忆”可以分成三种：会话/项目上下文、长期个人偏好、可复用的技能/工作流。Perplexity Max将Brain定义为为Computer提供工作上下文的自我改进记忆系统；Genspark与Kimi则把Skills、自进化技能或Memory作为产品能力；ChatGPT Work则强调项目资料、应用和工作流上下文。记忆越强，Agent越像“长期助手”；但同时也意味着更高的数据持续留存、权限和误用风险。[S11][S16][S19][S01]

六、关键场景分析

6.1 信息检索与深度研究

任务特征：多来源搜索、交叉验证、整理证据、形成报告。

典型Agent：Perplexity Computer、ChatGPT Work、Gemini Agent、Kimi Agent、Manus。

关键指标：来源覆盖度、引用准确率、事实核验率、遗漏率、报告可读性、总耗时。

注意：搜索“数量”不等于研究质量。Kimi Deep Research公开披露平均关键词、网址和筛选比例，只能说明其检索流程，不应直接推断事实准确率。[S19]

6.2 办公文档与汇报材料

任务特征：读取源文件、分析数据、形成Word/PPT/Excel。

典型Agent：ChatGPT Work、Claude、Kimi、Genspark、Manus。

关键指标：格式正确率、数据引用正确率、可编辑性、模板遵循度、返工率。

Claude已公开支持直接创建/编辑Excel、PowerPoint、Word和PDF；ChatGPT Work支持文档/表格/演示文稿；Kimi与Genspark也将Office类交付纳入Agent闭环。[S09A][S01][S19][S16]

6.3 网页事务操作

任务特征：筛选、填写、登录、提交、购买、预约、下载。

典型Agent：ChatGPT Agent、Gemini Agent、Perplexity Computer、Genspark、Manus。

关键指标：任务成功率、登录/验证码处理率、误操作率、人工接管次数。

高风险操作必须设计确认节点；OpenAI、Google等均明确对购买/发送等关键动作采用确认或人工接管。[S03][S04]

6.4 本地电脑与传统软件操作

任务特征：Excel桌面端、PDF工具、内部客户端、非标准网页系统。

典型Agent：Claude Desktop/Cowork、Kimi Work、QwenWork，以及部分Computer Use方案。

关键指标：像素级定位成功率、跨应用成功率、错误恢复、权限隔离。

QwenWork明确支持后台鼠标键盘控制；Anthropic支持本地Desktop Extensions；这类产品的价值在于绕过“每个软件都要开发API”的高门槛。[S23][S08]

6.5 重复性与持续性工作

任务特征：每天/每周运行、监控变化、自动输出。

典型Agent：ChatGPT Work Scheduled Tasks、Perplexity Computer、Kimi、QwenWork。

关键指标：准时率、空跑率、失败恢复率、成本可预测性。

持续运行是Agent从“工具”向“数字员工”演进的重要标志；但长期任务需要更强的预算、权限与日志管理。[S01][S10][S20][S24]

6.6 创作与多媒体复合任务

任务特征：研究→脚本→图片/视频→配音→剪辑→发布。

典型Agent：Genspark、Manus、Kimi、ChatGPT。

关键指标：流程完整度、素材一致性、可编辑性、最终交付时间。

Genspark将文本/图像/视频/音频模型和Super Agent统一为共享Credits体系；Manus与Kimi也把网站、PPT、视频等作为Agent成果物。[S17][S16][S19]

6.7 个人工作流示例：从“问问题”变成“交付结果”

传统方式：用户提出“分析某行业”，AI给出一份答案，用户仍要自己搜资料、整理Excel、制作PPT、发邮件。Agent方式：用户给定目标、口径和交付模板，Agent自主搜索并记录来源→下载/读取数据→清洗→分析→生成图表→形成Word/PPT→检查关键数字→等待用户确认→交付文件。这个过程把“信息加工”从多个软件和人工步骤，压缩到一个可追踪的任务闭环。ChatGPT Work、Perplexity Computer、Manus、Kimi和Genspark均公开展示了这类闭环能力的不同版本。[S01][S10][S13][S16][S19]

7.2 Credits为什么成为Agent时代的主流计量方式

长任务具有不可预测的token、搜索、工具调用和执行时间。传统“每月无限聊天”无法直接覆盖这种成本，因此厂商逐步引入Credits、任务次数、模型档位和速度档位。Manus按实际消耗扣Credits；Genspark根据文本长度、模型层级、生成数量以及任务复杂度计费；Kimi将多个Agent类产品共享统一额度池；Perplexity则将Computer、研究和素材生成等能力与积分结合。[S13][S17][S21][S12]

风险成本错误提交、数据泄露、越权操作潜在损失远高于订阅费高风险任务人工审批率与事故数

八、可靠性与Benchmark：为什么不能只看排行榜

8.1 三类Benchmark实际上测的是不同能力

Benchmark主要测什么环境适合回答的问题不适合回答的问题
OSWorld开放式真实电脑环境中的GUI任务真实桌面操作系统与应用Agent能否完成桌面操作任务不能直接代表所有办公/研究任务
WebArena / WebArena-Verified网页环境中的多步骤任务购物、Reddit、GitLab、Wikipedia等网页Agent的浏览/操作能力不能等价于真实互联网所有网站
GAIA综合知识任务＋工具使用多工具、多类型知识问题Agent的通用问题解决能力不是纯Computer Use测试

OSWorld官方站点在2026年6月公布OSWorld 2.0，并持续更新Verified基准；WebArena-Verified则强调人工审核任务、确定性评测和网络轨迹回放。不同benchmark的任务、环境和评测方法不同，不能把分数直接横向相加。[S31][S32]

8.2 为什么Agent会出现“单次成功、长期不稳定”

Agent是多步骤系统。假设一个任务需要10个步骤，即便每步成功率为95%，在最简单的独立假设下，整条链路的理论成功率约为0.95^10≈59.9%。真实系统还存在状态污染、网页变化、工具异常、上下文漂移、并发冲突等问题，因此长任务的整体成功率通常会明显低于单步能力。这个公式是数学推演，不是某家产品实测数据；它用于解释“为什么步骤越多，可靠性越难维持”。Anthropic也明确把Agent的“错误累积”作为重要风险。[S27]

8.3 可靠性评价建议

指标定义推荐权重示例为什么重要
任务完成率在给定任务集上一次性达到验收标准的比例30%最核心结果指标
关键步骤正确率登录、筛选、填写、提交等关键节点正确率20%发现“最后一步出错”问题
事实/数字准确率输出与源数据一致的比例15%知识工作核心质量
人工介入率需要用户补充/纠正/接管的任务比例10%反映真正节省了多少人力

平均耗时从启动到交付的时间5%与生产效率直接相关
单位成功任务成本总订阅/积分成本折算到成功任务5%控制Agent经济性
风险事件率误操作、越权、敏感数据暴露等5%高风险场景不能缺失

上表权重只是一个可执行的企业/个人评测模板，不是行业标准。实际选择权重时，应根据任务风险重新调整。高风险操作应把安全与审批权重提高。

九、安全、隐私与治理

9.1 Agent相比聊天机器人多了什么风险

聊天机器人主要产生“信息风险”；Agent额外产生“行动风险”。当Agent可以读取邮件、文件、登录网站、操作账户、修改文档、运行代码时，风险从“回答错误”扩展到“执行错误”。OpenAI官方明确将提示注入、数据外泄和错误操作作为Agent特有风险，并指出提示注入可能诱导Agent泄露连接器数据或执行非预期动作。[S03][S39]

9.2 提示注入（Prompt Injection）为何是Agent的结构性风险

网页、邮件、文档中的文本对普通聊天来说通常只是输入；对Agent来说，它们可能同时包含“可执行指令”。攻击者可以把恶意指令埋进Agent将要读取的网站内容中，试图改变任务目标、获取敏感信息或诱导错误操作。OpenAI的系统卡将其定义为Agent重点风险，并采用安全训练、监控、用户确认、Watch Mode和网络限制等多层缓解机制。[S03]

9.3 OWASP给出的治理方向

OWASP在《Top 10 for Agentic Applications 2026》中将Agentic系统的关键安全问题系统化，目标是帮助开发者和部署者处理自主Agent在复杂工作流中的风险。对个人用户最重要的不是记住十个名词，而是形成“最小权限＋高风险确认＋可审计＋可撤销”的四原则。[S33]

9.4 产品安全机制的横向观察

机制典型实现解决的问题仍然存在的边界
人工确认购买/发送/提交前确认降低高影响误操作确认本身不等于理解风险
人工接管Take over / Watch Mode用户介入登录或敏感网页会增加操作成本
沙盒云端虚拟机/文件系统将Agent执行环境与本机隔离沙盒中的数据仍可能敏感
最小权限只连接任务所需App降低数据与权限暴露面用户往往倾向于“一次授权所有”
审计日志工具调用记录/执行过程可追溯错误和责任个人产品的日志深度通常低于企业系统
预算/额度Credits、次数、并发限制控制失控任务和成本额度不足会中断任务

9.5 隐私选型：本地 vs 云端

Anthropic官方把Local Desktop Extensions与Remote Web Connectors明确区分：本地扩展在用户电脑上运行，可访问本地文件、应用和系统资源；远程连接器在外部服务器上运行，用于连接云端服务。[S08] QwenWork则同时提供云端Agent、客户端Computer Control以及云端定时任务；因此“本地”和“云端”并不是二选一，而是一种混合架构趋势。[S22][S23][S24]

对于企业敏感资料，建议将数据分为公开、内部、敏感、受监管四级，再分别决定允许的Agent类型。尤其不要把“能连接”理解为“应该连接”：邮箱、网盘、企业聊天、财务系统、理赔/客户资料等一旦被Agent获得，就可能成为高价值攻击面。

十、技术生态：MCP、A2A 与 Agent 工具协议

10.1 MCP：让Agent更容易连接工具与数据

Anthropic在2024年提出Model Context Protocol（MCP），目标是建立连接AI助手与数据/工具的开放协议。2026年MCP路线图进一步把可扩展传输、Agent通信、治理成熟度和企业级能力列为重点，说明MCP已经从“连接工具”逐步向Agent生态基础设施演进。[S29][S27]

10.2 A2A：让Agent之间可以协作

Google在2025年发布Agent2Agent Protocol（A2A），强调不同厂商、不同框架下的Agent可以互相协作，从而形成跨系统的多Agent生态。[S30] 对个人Agent而言，这意味着未来可能出现“主Agent负责目标→专业Agent负责订票/研究/编程/财务→主Agent汇总”的模式。

10.3 MCP与A2A不是一回事

维度MCPA2A
主要解决Agent/模型与工具、数据源的连接Agent与Agent之间的协作与互操作
典型关系“让我能调用一个工具”“让我能委派给另一个Agent”
价值降低连接成本、扩大工具生态降低多Agent协作中的厂商锁定
对个人产品的意义更多Apps/服务可被Agent使用未来可形成Agent网络与专业Agent市场

10.4 产品竞争将从“模型能力”逐渐转向“生态能力”

当多个产品都能调用相近级别的基础模型时，用户真正感知差异的因素会转向：连接了多少真正有用的应用；能否稳定操作真实网站/电脑；能否保持任务状态；能否复用技能；能否安全执行高影响动作；能否让用户低成本检查结果。2026年的产品路线已经明显朝这一方向发展。[S01][S08][S10][S16][S19][S22]

十二、个人选型方法：不看“谁最强”，而看“哪种执行环境适合我”

12.1 第一判断：任务究竟是“信息问题”还是“行动问题”

如果最终答案只是“告诉我是什么”，优先选择搜索/聊天产品即可；如果最终结果必须是“帮我把它做完”，才需要Agent。如果任务涉及登录网站、整理文件、改表格、生成PPT、发邮件、持续监控，那么浏览器/电脑/连接器能力比模型排行榜更重要。

12.2 第二判断：工作资料在哪里？

资料位置优先关注的产品能力原因
本地电脑Desktop Agent / Computer Use无需把每一步都复制到聊天窗口
Google生态Gemini Agent + Gmail/Calendar/Docs原生账户与数据连接更顺畅
Microsoft生态Copilot/Workflows + M365 Agents组织权限与Office流程结合
多云互联网资料Perplexity Computer / ChatGPT Work / Manus搜索＋研究＋执行一体化
中文Office与本地工作Kimi Work / QwenWork中文生态、本地桌面和Office场景适配
高频创作与多媒体Genspark / Manus / Kimi多模型、多媒体、交付物一体化

12.3 第三判断：我要“在场监督”，还是“离开电脑也能继续做”

模式典型要求关注功能
实时陪跑我边看边纠偏过程可见、人工接管、Watch Mode
半自动Agent做80%，关键节点问我审批、确认、回滚、暂停
后台自动我下班后它继续做云端持久会话、任务调度、失败重试
持续运营每天/每周自动运行定时、触发、监控、记忆、成本预算

12.4 第四判断：我能接受什么级别的权限？

建议个人用户建立“权限阶梯”：公开网页浏览＜普通文件读写＜工作资料读写＜邮件/聊天读取＜邮件发送＜交易/支付＜账户设置/删除。越往后，越应使用人工确认、专用账号、最小权限和可回滚机制。

十三、个人Agent使用的标准工作流模板

13.1 “目标—边界—证据—执行—验收”五段式提示

阶段提示信息示例要求
目标最终交付是什么“输出一份20页行业分析报告”
边界范围、时间、预算、禁区“只使用2025-2026公开资料；不引用论坛传言”
证据来源等级与引用规则“所有关键数据必须有一手来源；引用网址/发布日期”
执行是否允许自主搜索、运行代码、修改文件“允许读取指定文件、运行代码；购买/发送邮件前必须询问”
验收最终结果的质量门槛“检查数字一致性、引用、文件格式、目录、图表和结论逻辑”

13.2 适合Agent的任务特征

步骤多，但每一步都存在可观察反馈；

目标明确，结果可以验收；

需要在多个工具之间搬运/加工信息；

重复性较高，人工步骤繁琐；

低频判断＋高频执行；

能够容忍少量人工审批。

13.3 不适合完全交给Agent的任务

无法清晰定义成功标准的任务；

不可逆、资金高、法律后果高且缺少审批的任务；

需要大量隐性组织政治/人际关系判断的任务；

资料来源本身不可验证的任务；

一旦错误就会造成重大损失、而系统又没有回滚机制的任务。

十四、企业/组织导入Agent的建议框架

14.1 不建议从“买一个最强Agent”开始

企业导入Agent的核心不是采购一个聊天工具，而是建立“任务库＋权限体系＋工具连接＋评测集＋监控机制”。Deloitte 2026调查显示，企业Agent使用增长快于治理成熟度；McKinsey也指出，Agent的规模化使用仍处在早期阶段。因此组织应把Agent当成新型工作基础设施，而不是员工个人工具。[S35][S36][S37]

14.2 推荐的四层企业Agent架构

层级建设内容关键问题
员工层个人Agent入口、模板、Skills员工能否低门槛创建任务？
工具层MCP/API/Connectors/Computer UseAgent能否获取正确数据并执行正确动作？
治理层身份、权限、审批、审计、预算谁允许Agent做什么？出了问题谁能追踪？
评估层任务集、自动检查、人工复核、指标如何证明Agent真的节省时间且没有放大风险？

14.3 组织级评测必须使用“自己的真实任务集”

建议从20—50个真实高频任务开始，按低、中、高风险分组，每个任务准备明确的输入、允许工具、标准答案/标准结果和验收条件。比较不同Agent时统一浏览器环境、统一文件、统一权限和统一验收标准，记录成功率、耗时、人工介入率和成本。这样比直接引用厂商benchmark更能预测实际生产价值。[S31][S32]

十五、未来12—24个月的产品趋势判断（基于已公开路线）

15.1 从“单一Agent”走向“Agent运行时”

MCP、A2A、Skills、Connectors、Sub-agents等共同说明，产品竞争正在从“一个聊天模型”转向“一个可编排的Agent运行时”。未来用户可能不再关心后台究竟调用哪个模型，而只关心目标、权限、成本和结果。[S29][S30]

15.2 浏览器会变成Agent的重要“身体”

Browser Agent和Computer Use解决的是同一个更深的问题：让AI不只读网页，而是能在网页和软件里行动。Google、OpenAI、Anthropic、Perplexity、QwenWork以及Genspark等路线都在加强浏览器/电脑操作。[S04][S03][S08][S10][S16][S23]

15.3 个人Agent将越来越“长期化”

一次性任务只是Agent的第一阶段。后台任务、周期任务、记忆、Skills、项目空间、监控和持续执行，正在把Agent从“工具”转化为“数字助手”。Perplexity Computer、ChatGPT Work、Kimi Work、QwenWork都已公开提供不同形式的持续任务机制。[S10][S01][S20][S24]

15.4 “验证器/审计器”会和执行Agent同等重要

越能做事的Agent，越需要一个“检查自己做得对不对”的层。可能出现的标准架构是：主Agent执行→独立Verifier检查证据/格式/数字→必要时重新执行→Human Approval→交付。Anthropic公开介绍的Evaluator-optimizer模式，以及多Agent系统的并行/聚合模式，都指向这一方向。[S27]

15.5 Agent经济学最终取决于“单位成功任务成本”

当订阅费、Credits、模型费用和人工复核成本都进入同一条链路后，真正有意义的经济指标将是“完成一个标准任务花多少钱、节省多少人工时间、造成多少返工和风险”。这也是为什么高端Agent产品已经普遍采用积分、额度和用量管理。[S13][S17][S21][S12]

十六、综合判断：通用任务型个人 Agent 当前处于什么阶段

综合公开资料，本报告认为2026年9月的通用个人Agent已经跨过“概念验证期”，进入“真实工作可用，但仍需人类监督”的阶段。其能力边界已经明显超过传统聊天机器人，尤其在研究、文档、网页操作、代码、数据分析和多工具协同上。但“能完成一次任务”与“稳定承担一个岗位”仍然存在明显差距。[S34][S31][S36]

最终判断

个人Agent的核心产品价值已经从“提高回答质量”转变为“降低完成任务的人工步骤数”。未来真正具有竞争力的产品，必须同时解决四件事：第一，理解用户目标；第二，能够在真实软件/网页环境中采取行动；第三，能够长期保留任务状态并恢复失败；第四，在执行边界、数据权限和成本上让用户保持控制。单一模型能力仍重要，但已经不足以决定一个通用Agent产品的实际价值。
