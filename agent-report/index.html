核心判断：2026年的个人 Agent 已进入“真实工作可用、仍需人类监督”的阶段。产品价值应以任务成功率、人工介入率、返工率、单位成功任务成本和风险事件率衡量，而不是只看模型 benchmark。

一、执行摘要

通用任务型个人 Agent 的核心是“目标—规划—行动—反馈—交付”闭环：推理模型负责理解与规划，浏览器/电脑操作和工具负责行动，环境反馈负责纠错，文件/应用/项目状态负责持续执行，最终交付可验收成果。

  • 市场形成三类产品路径：超级助手型、云端数字员工型、电脑/浏览器接管型。
  • Computer Use 是关键基础能力，因为真实工作大量依赖网页、桌面软件和旧系统 GUI。
  • 长任务效率越来越依赖并行子任务、编排器、聚合器和失败恢复。
  • 行动能力带来新的提示注入、越权、数据外泄和误操作风险。
  • 厂商 benchmark 不能直接代表真实互联网任务成功率，选型应做统一任务集实测。

二、研究口径与成熟度

纳入标准：多步骤规划、至少一种外部工具/数据源/文件/网页/应用访问、一定程度自主行动、面向个人知识工作，并能交付文档/表格/PPT/代码/网页/分析结果等成果。

等级典型特征主要瓶颈
L0 对话助手回答、生成内容幻觉、上下文
L1 工作流助手固定流程、多工具串接灵活性
L2 浏览器 Agent看网页、点击、输入网页变化、登录、提示注入
L3 电脑 Agent桌面应用、文件、终端权限、可逆性、恢复
L4 持续/多Agent后台、并行、记忆、技能成本、状态一致性、安全

三、从 Chat 到 Agent

产品竞争焦点已经从“回答质量”向“执行闭环”迁移。API/MCP、浏览器自动化、Computer Use 是三种主要工具获取路径。它们分别代表结构化、高通用低结构化和直接 GUI 执行能力。

真正的分水岭不是有没有 Agent Mode，而是能否跨多个工具持续执行、失败后恢复、安全处理副作用、保留任务状态，并让用户理解和干预。

七、安全与治理

  • 人工确认：购买、发送、提交等高影响动作前确认。
  • 人工接管：登录、敏感网页和复杂步骤允许用户接手。
  • 沙盒：隔离执行环境，降低对本机系统影响。
  • 最小权限：只连接完成任务所需的数据和应用。
  • 审计日志：记录关键工具调用和动作。
  • 预算/额度：限制失控任务和成本。
高风险任务原则：不可逆、资金高、法律后果重、成功标准不清或没有回滚机制的任务，不应默认交给 Agent 无人值守。

九、20项真实任务评测框架

指标权重核心问题
任务完成率30%是否一次达到验收标准
关键步骤正确率20%登录/筛选/填写/提交是否正确
事实/数字准确率15%是否与源数据一致
人工介入率10%真正节省多少人力
返工率10%交付后大修比例
平均耗时5%生产效率
单位成功任务成本5%订阅/积分/人工
风险事件率5%误操作/越权/泄露

建议20项任务覆盖：研究、网页浏览、Excel清洗、PPT交付、文档编辑、电脑操作、登录权限、错误恢复、30分钟长任务、并行任务、定时任务、引用核验、隐私边界、高影响审批、停止接管、可编辑交付物、成本、稳定性、可复现性和主观体验。

十、未来12—24个月趋势

  • 从单一Agent走向Agent Runtime。
  • 浏览器/电脑成为Agent的重要“身体”。
  • 后台任务、周期任务、Memory、Skills、项目空间推动个人Agent长期化。
  • Verifier/审计器与执行Agent同等重要。
  • 产品竞争最终围绕单位成功任务成本。
综合判断：个人 Agent 已跨过概念验证期，但距离“稳定承担一个岗位”仍有明显差距。高价值场景应优先选择结果可验收、步骤可观察、错误可恢复且允许人工审批的任务。
